# Personal fork of Herdr (the desktop app)

Fork `schugazi/herdr-app` of upstream `herdrdev/herdr-app`; read upstream's `AGENTS.md` for the code. Edited in `~/herdr-app` on mycroftxxx (branch `master`), built and installed on multivac from `C:\Users\nmsch\herdr-app` with `scripts/fork-install.ps1` (CI's toolchain: Rust 1.95.0, Zig 0.16.0 in `%LOCALAPPDATA%\Programs`, LLVM for bindgen, VS Build Tools). This host can't build it (no GUI dev packages here).

The fork adds settings.json `cursor_style`, `cursor_blink` and `cursor_thickness` (the terminal cursor's default, its blink, its thickness; `src/vt.rs`, `src/terminal.rs`, `defaults/AGENTS.md`), and a desired-state zoom: `pane.zoom {pane, on}` sets it (no `on` still toggles; with `on` a lone pane is "nothing to zoom") and `ls` gives each tab's `zoomed` (`src/window.rs` `zoom_pane` and `world()`, `src/commands.rs`, `defaults/AGENTS.md`, `src/SKILL.md`). It also keeps the focused pane's highlight border while a frameless popup holds the keyboard (a key catcher such as `~/herdr-app-mods`' `prefix`; `focused_path` in `src/window.rs`). Its editor highlighter names more scopes for `EditorState`'s `syntax` map: property (JSON, YAML and JS keys, CSS properties, members), tag, attribute, and markdown's heading, bold, italic, code and link, and diff's inserted and deleted, plus finer names that fall back to their root (keyword.control, variable.language, type.namespace and the rest `typings.rs` lists, which Python's grammar fills); quotes take their string's color and comment marks their comment's (`vendor/gpui-kit/crates/shell/src/syntax.rs`, `typings.rs`). Mods get `reloadImage(path)`, which drops one picture from GPUI's asset cache so a frame file rewritten under `data/` shows again (`src/mods.rs`, `Request::ReloadImage` in `src/window.rs`, `defaults/herdr.d.ts`; `~/herdr-app-mods`' `schu-browser` needs it). Mods also get `highlight(language, text)`, the editor's highlighter for code they draw themselves: each line's pieces with the `syntax` name that colors them, on a worker thread (`highlight_lines` in `syntax.rs`, `src/mods.rs`, `defaults/herdr.d.ts`; `~/herdr-app-mods`' `schu-changes` colors its diff with it). Each mod function the fork adds is also registered in the render tests' `herdr` fixture (`module` in `src/mods/render_tests.rs`), since a module must register every function `herdr.d.ts` declares. Overlay windows opened with `resizable: true` resize from their left, right and bottom edges and both bottom corners, and a keyed one remembers its size in `windows.json` `sizes` (`src/window/movable.rs`, `Overlay.resizable` in `src/window.rs`, `defaults/AGENTS.md`, `defaults/herdr.d.ts`; `~/herdr-app-mods`' Dispatch window uses it). When the tab area changes, only the shown space's hidden tabs are sized to it (`fit_hidden_tabs` in `src/window/pane_size.rs`): side panels remembered per tab (`~/herdr-app-mods`' `schu-tabs`) give each tab its own area, so sizing every space's resized their programs on each switch. Limit: the shown space's hidden tabs still take the shown tab's area, so switching between two tabs of a space with different side panels makes Claude Code reflow on each switch; leaving those tabs unsized too would end it. A terminal's size on screen reaches its program 100 ms after it first changes, and not at all if it changed back meanwhile (`Grid::settle` in `src/terminal.rs`; sizes before it attaches and with a new cell (font size, zoom) go out at once, a drag resizes every 100 ms, a pane shown again waits afresh), so a switch's frame or two with the last tab's side panels doesn't make Claude Code redraw twice. `.sql` files use its own T-SQL grammar (`crates/shell/src/tsql.sublime-syntax`, loaded through syntect's `yaml-load` feature) instead of syntect's default SQL, which reads `#temp` tables as comments. A Ctrl+click on a path in a terminal on another machine (an address with a `machine/` prefix) never checks this computer's disk, where the path means nothing: the path as shown (relative, `~/`, `:line`; there also a bare `README.md:12` or `src/Makefile:12`, `links::BARE`, which Ghostty's pattern misses), or a `file:` URL's decoded when its host is none, `localhost`, the machine's name or its core's host name, exactly or as the short name of one given in full (`machine.list` `host`, which differs for multivac-wsl; agy's links, `ls --hyperlink`, Claude Code's with `FORCE_HYPERLINK`), goes to mods as the shared `herdr.link` (`{id, terminal, path, cwd, at}`, `at` in ms on this computer's clock), and mods look for it on that machine (`links::find_remote`, `MACHINE_HOSTS`, `LinkTarget::Remote` and `hand_link_to_mods` in `src/terminal.rs`; `~/herdr-app-mods`' `schu-tabs` opens it in `schu-files`). Such a path links unchecked, so only on its own line (not across lines a program broke itself) and only when it isn't a live terminal's address; URLs there, a `file:` URL naming another host too, open here as before, and terminals on this computer keep upstream's behavior. Ghostty's pattern here differs in one place: a scheme never starts inside a word or path (`Makefile:12` and `src/build-file:12` aren't the URL `file:12`). The terminal right-click menu's props carry the clicked terminal's selected text as `target.selection` (null when none; `TerminalEvent::ContextMenu` in `src/window.rs`), for `~/herdr-app-mods`' `schu-pane-menu` Open in Files. A mod editor's selection is the theme's `selection` color, as upstream now has it too, except that a theme selection its text can't be read on (under 4.5:1, Win98's navy under black) keeps `accent` at 40% (`InputEditorStyle::resolved` in `vendor/gpui-kit/crates/base/src/input/editor/highlighting.rs`). Fork-only files: this one, `scripts/fork-install.ps1`, `.claude/skills/sync-upstream/`.

A build from source never updates itself or any core, so updates are by hand via `/sync-upstream`: the app takes upstream's latest release tag by merge, never rebase and never `upstream/master`; every core goes to the latest stable core release the app is compatible with, assessed on its own each run. Host setup and the cores: `~/.local/share/herdr-app/README.md` on mycroftxxx.
